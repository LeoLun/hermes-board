## 为什么做

用户希望在 Hermes Desktop 里有一个可以自定义的卡片式看板，内容由 Hermes 在对话中按需生成。每张卡片是一个独立 HTML，数据由远程主机上的脚本采集，存进规范的 SQLite，由 Hermes 原生 cron 定时刷新；卡片里点击按钮也能触发远程脚本。这样任何“查看某种状态 / 执行某个操作”的需求，都可以通过一次对话变成看板上的一张卡片，而且样式统一、数据规范、可以自动刷新。

## 已确认的约束

1. 架构为“本机 Hermes Desktop + 远程 Hermes 服务”。远程权威保存卡片 HTML、脚本、数据、布局和定时任务，Desktop 只负责渲染和交互。
2. Desktop 侧边栏新增一项“看板”。看板页面由卡片组成，每张卡片是一个独立加载的 HTML 文件。
3. 鼠标移到卡片左下角或右下角时出现圆弧提示，光标变为调整大小，可以拖拽调整尺寸；松手时吸附到固定的预设尺寸。
4. 鼠标移到卡片上方中间时出现横条，按住横条可以拖动卡片位置。
5. 整个看板的布局（每张卡片的位置和大小）用 JSON DSL 存储。
6. 看板页面右下角有“自动整理”按钮：只调整位置、不改大小，让卡片尽可能紧密排布。
7. 用户可以通过对话让 Hermes 创建卡片，靠的是插件提供的技能和工具。
8. 服务端规范 HTML 存放位置，支持用脚本生成数据，数据统一存进 SQLite，并通过受控接口提供给卡片 HTML。
9. 卡片 HTML 遵循统一标准，视觉参考 [Apple DESIGN.md](https://github.com/VoltAgent/awesome-design-md/blob/main/design-md/apple/DESIGN.md)。
10. 卡片 HTML 可以触发指定脚本做后续操作。
11. 初始化时放入天气、时钟、番茄钟等通用卡片，铺满页面。
12. 有不确定的地方必须先和用户确认。

## 方案比较与选择

### 卡片承载方式

| 方案 | 收益 | 代价 | 结论 |
|---|---|---|---|
| A. Desktop 通过 `ctx.rest` 拉取 HTML，注入运行时和 CSP 后转成 `data:` URL，放进 `SandboxedFrame`；卡片通过 postMessage 桥访问数据 | 适用于任意远程网关（包括 OAuth）；凭据不会进入卡片；卡片无法接触 App 权限或其他卡片；安全边界由渲染侧掌控 | 需要自己实现桥协议；HTML 大小受 data URL 长度限制 | **选择** |
| B. `SandboxedFrame` 直接加载远程 `http(s)` 的卡片地址 | 实现简单 | 需要把凭据放进 URL，OAuth 远程下无法使用，origin 不透明时也带不了 cookie | 不选 |
| C. 把卡片写成 Desktop 插件的 React 组件 | 渲染最自然 | 卡片代码会拿到完整 App 权限，也不符合“独立 HTML 文件”的要求 | 不选 |

### 数据存储

推荐并选择**一个 `board.sqlite3`，使用统一的标准表**：数据集快照、时间序列、卡片状态、运行记录、变更流水。所有表都按卡片 id 隔离。另一种做法是每张卡片一个自定义结构的数据库，但这样无法统一读取接口和保留策略，不选。

### 定时刷新

用户已选：**每个需要定时运行的脚本对应一条 Hermes 原生 cron 任务**（`no_agent=True`，名称为 `hermes-board:<卡片>:<脚本>`），可以在 Hermes 定时任务页面查看、暂停、查看失败。不采用“单一调度任务统一分发”的方案。

## 本次变更范围

### 包含

- 统一插件包 `hermes-board`：`plugin.yaml`、Agent 工具 `board_manage`、技能 `hermes-board:card-author`、远程 REST API，以及 Desktop 插件。
- Desktop 看板：侧边栏入口和页面路由，24 列网格渲染，悬停显示横条和圆角调整手柄，拖动、吸附预设尺寸、推挤冲突卡片，右下角“自动整理”，“添加卡片”列表，右键菜单（刷新、最近运行、移除），跟随主题，以及各种错误和空状态。
- 布局 DSL `board.json`：结构定义、校验、乐观并发版本号和冲突处理。
- 卡片包标准：存放位置、`card.json` 清单、单文件 HTML 规范、基于 Apple DESIGN.md 的设计令牌和组件类、安装前校验（lint）。
- 卡片运行时 `window.HermesCard`：读数据集、序列和状态，读写卡片自身状态，运行脚本，AI 结构化调用，订阅变更，环境与尺寸事件，提示与提醒，格式化工具和图表组件。
- 数据脚本：Python SDK `hermes_board_sdk.py`、SQLite 标准表和保留策略、点击触发脚本的执行器、原生 cron 同步（创建、更新、暂停、恢复、清理）。
- 首次初始化：安装 8 张默认卡片（天气、时钟、日历、世界时钟、倒数日、番茄钟、便签、待办），以 24×16 无缝铺满的布局展示。天气默认城市为北京。
- 测试：Python 单元测试，JS 纯逻辑测试，Python 与 JS 共用的布局测试用例；安装说明和人工验证清单。

### 不包含

- 机器监控、XRay 节点测速与切换、账单月度折线等业务卡片。之后由用户通过对话创建。本次只验证平台能力能覆盖这几类需求，详见 design.md 的“能力覆盖检查”。
- 多看板界面、卡片市场或分享、跨卡片读数据、同一卡片包放置多个实例。
- 在 Desktop 里上传、编辑卡片源码（卡片只能由 Agent 工具或内置默认包安装）。
- `hermes dashboard` Web 仪表盘端的插件界面、移动端。
- 卡片 HTML 直接联网（统一由远程脚本取数），远程主机的权限提升配置（比如 sudo 规则）。

## 影响

- 新仓库内容：Python 插件代码、Desktop 打包产物、卡片运行时、默认卡片包、技能文档、测试。
- 远程主机：新增 `$HERMES_HOME/plugin-data/hermes-board/`、`$HERMES_HOME/scripts/hermes-board/`，以及若干名称以 `hermes-board:` 开头的 cron 任务。
- 本机：新增 `$HERMES_HOME/desktop-plugins/hermes-board/`，侧边栏多一项“看板”。

## 成功标准

1. 远程安装并启用插件、Desktop 安装并启用 Desktop 端之后，侧边栏出现“看板”。首次打开时，8 张默认卡片无缝铺满 24×16 网格，天气卡片显示北京天气。
2. 拖动、调整尺寸、自动整理都按规格工作。结果写入远程 `board.json`，刷新页面或在另一台 Desktop 打开时看到的布局一致。
3. 在对话中描述一个新需求，Hermes 能借助技能和 `board_manage` 生成一张通过校验、风格一致的卡片：有脚本、写入 SQLite、按 cron 刷新，并且卡片内的按钮能触发脚本。整个过程不需要手动改文件。
4. Desktop 连接 OAuth 远程（没有 WebSocket）时，数据和布局更新仍能通过轮询在 10 秒内反映出来。
5. 卡片 HTML 无法发起网络请求，无法访问 App 或其他卡片的数据，越权调用会被拒绝并记录。
