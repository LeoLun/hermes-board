# 能力规格：Desktop 看板页面与交互

状态：已确认（2026-10-31 16:10 用户指示进入计划阶段）。网格、尺寸和管理范围对应 [proposal.md](../../proposal.md) 确认记录的第 6 到 8 项，技术细节见 [design.md](../../design.md) 第 5 节。

## ADDED Requirements

### Requirement: 侧边栏入口与页面
系统 MUST 在 Hermes Desktop 的侧边栏中注册“看板”导航项（codicon `dashboard`），点击后在主工作区打开路由 `/hermes-board` 的看板页面。命令面板中 MUST 提供“打开看板”“看板：自动整理”“看板：重新加载”。插件在 Capabilities → Plugins 中可以随时启用或停用；停用后所有入口立即消失。

#### Scenario: 启用后打开看板
- **GIVEN** 远程已启用 hermes-board 后端，本机已启用 Desktop 端。
- **WHEN** 用户点击侧边栏中的“看板”。
- **THEN** 主工作区显示看板页面，加载当前连接 profile 的布局和卡片。

#### Scenario: 远程后端未安装或未启用
- **GIVEN** 当前网关上 `/api/plugins/hermes-board/health` 返回 404。
- **WHEN** 用户打开看板。
- **THEN** 页面显示安装或启用指引，包括远程需要执行的命令和重启提示，不会显示空白页面或报错堆栈。

### Requirement: 24 列方形网格渲染
系统 MUST 按布局 DSL 在 24 列网格上渲染卡片。格子为正方形，格宽根据页面宽度计算，并限制在 24–72px；达到上限时看板居中，达到下限时出现横向滚动，纵向可以无限滚动。每张卡片 MUST 用 18px 圆角外框裁切，外框只使用 Hermes 主题变量。

#### Scenario: 调整窗口宽度
- **GIVEN** 看板上已有若干卡片。
- **WHEN** 用户把窗口从 1280px 拉宽到 1600px。
- **THEN** 卡片按新的格宽等比放大，格坐标不变，每张卡片都收到新的像素尺寸事件。

### Requirement: 悬停手柄
系统 MUST 在卡片 iframe 上方提供宿主覆盖层。鼠标移到卡片顶部中间的热区时显示胶囊横条，光标变为 `grab`。鼠标移到左下角或右下角热区时，沿卡片圆角显示圆弧，光标分别变为 `nesw-resize` 或 `nwse-resize`。手柄以外的区域 MUST 把鼠标事件交给卡片内容。卡片只允许一种尺寸时 MUST NOT 显示调整手柄。

#### Scenario: 悬停右下角
- **GIVEN** 卡片允许多种尺寸。
- **WHEN** 鼠标进入卡片右下角 24×24px 的区域。
- **THEN** 该角出现圆弧提示，光标变为 `nwse-resize`；离开后提示消失。

#### Scenario: 点击卡片内部按钮
- **GIVEN** 卡片中部有一个按钮。
- **WHEN** 用户点击这个按钮。
- **THEN** 点击由卡片 HTML 接收，不会触发移动或调整。

### Requirement: 拖动移动卡片
系统 MUST 允许按住横条拖动卡片：拖动中卡片跟随指针，目标位置吸附到格子并限制在 24 列内，同时实时预览落点和受影响卡片的推挤结果。松手后提交一次布局写入；按 Esc 取消并还原。拖动期间所有 iframe MUST 不接收鼠标事件。

#### Scenario: 拖到有卡片的位置
- **GIVEN** 卡片 A 在 (0,0)，大小 8×8；卡片 B 在 (8,0)，大小 8×4。
- **WHEN** 用户把 B 拖到 (0,0) 后松手。
- **THEN** B 放在 (0,0)，A 往下移到刚好不重叠的位置（`y=4`），其他卡片如有冲突则连锁下移，结果写入远程 `board.json`。

#### Scenario: 拖动中按 Esc
- **WHEN** 用户拖动卡片时按下 Esc。
- **THEN** 所有卡片回到拖动前的位置，不写入布局。

### Requirement: 调整尺寸并吸附预设
系统 MUST 允许拖动左下角或右下角手柄调整尺寸。右下角固定左上角，左下角固定右上角。尺寸只能取“全局预设（4×4、4×6、6×4、6×6、8×4、8×6、8×8、12×6、12×8）∩ 卡片声明的 sizes ∩ 能放进 24 列”中的值；拖动时选与指针期望尺寸最接近的候选，并显示 `宽×高` 标签预览。冲突卡片按推挤规则下移。松手后提交，卡片 HTML 收到新尺寸。

#### Scenario: 从左下角放大
- **GIVEN** 卡片在 (8,0)，大小 4×4，允许 4×4、6×4、8×4。
- **WHEN** 用户把左下手柄向左下方拖动，期望尺寸约为 7.6×4.3。
- **THEN** 预览吸附为 8×4，右边缘保持在第 12 列，`x` 变为 4；松手后写入布局。

#### Scenario: 没有可容纳的候选尺寸
- **GIVEN** 卡片紧贴右边缘，右下手柄能取的更宽尺寸都会超出 24 列。
- **WHEN** 用户继续向右拖动。
- **THEN** 只考虑能放下的候选尺寸，都放不下时保持原尺寸，不出现越界布局。

### Requirement: 自动整理
系统 MUST 在看板页面右下角固定显示“自动整理”按钮。点击后只改位置、不改尺寸，按 design.md 第 5.4 节的确定性算法让卡片尽可能紧密排布（优先总高度最小，其次位移总和最小），用动画过渡，写入一个新版本，并提供“撤销”。已经最紧凑时 MUST 提示且不写入。

#### Scenario: 有空洞的布局
- **GIVEN** 卡片之间有因推挤留下的空行。
- **WHEN** 用户点击“自动整理”。
- **THEN** 所有卡片尺寸不变，没有重叠，总高度不超过整理前，结果持久化。

#### Scenario: 撤销整理
- **WHEN** 用户在整理完成的提示中点击“撤销”。
- **THEN** 整理前的布局作为新版本写回。

### Requirement: 添加与移除卡片
系统 MUST 在页面头部提供“添加卡片”入口，列出已安装但不在看板上的卡片，选中后按默认尺寸放到首个空位。系统 MUST 在卡片菜单中提供“从看板移除”：只修改布局并暂停该卡片的 cron，MUST NOT 删除卡片包或数据。

#### Scenario: 移除后重新添加
- **GIVEN** 用户把“便签”移出看板。
- **WHEN** 用户之后在“添加卡片”里重新选择“便签”。
- **THEN** 便签回到看板，之前的文本内容还在。

### Requirement: 卡片菜单与运行状态
系统 MUST 在右键卡片任意位置或横条时弹出宿主菜单，包含“刷新”“立即运行 ‹脚本›”“最近运行”“关于此卡片”“从看板移除”。“最近运行”MUST 显示该卡片每个脚本最近的状态、时间、耗时和错误摘要。

#### Scenario: 查看失败的运行
- **GIVEN** 天气脚本最近一次因为网络超时失败。
- **WHEN** 用户打开“最近运行”。
- **THEN** 看到状态为“超时”或“失败”的记录、时间和 stderr 摘要，并可以“立即运行”重试。

### Requirement: 主题、状态与容错
系统 MUST 让看板外框跟随 Hermes 主题，并把浅色或深色模式实时传给每张卡片。单张卡片加载失败（10 秒内没有发出 ready）、清单不合法或卡片包不存在时，MUST 只影响这一张卡片，显示可重试或可移除的状态。连接断开时 MUST 保留最后的画面并标记“已断开”，恢复后自动重新同步。

#### Scenario: 切换到深色主题
- **WHEN** 用户在 Hermes 中切换到深色主题。
- **THEN** 看板外框和所有卡片同时切换到深色令牌，卡片不需要重新加载。

#### Scenario: 一张卡片脚本报错
- **GIVEN** 某张卡片的 HTML 抛出未捕获的异常。
- **WHEN** 看板正在渲染。
- **THEN** 其他卡片正常显示，只有这张卡片显示错误状态。

### Requirement: 键盘可达（SHOULD）
系统 SHOULD 允许聚焦卡片的移动横条后用方向键按 1 格移动，用 `Shift+方向键` 在允许的尺寸之间切换，按 Enter 或失焦时提交。

#### Scenario: 键盘移动
- **WHEN** 用户聚焦横条后按两次右方向键再按 Enter。
- **THEN** 卡片右移 2 格（遇到冲突时推挤），写入布局。
