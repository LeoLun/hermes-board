# 看板桌面端增量规格

## 自动整理稳定性

系统 MUST 在滚动容器中预留稳定的纵向滚动条槽位，使内容高度变化不改变网格可用宽度。系统 MUST 在自动整理请求执行及布局提交期间关闭卡片位置和尺寸的过渡动画，并在提交结束后恢复正常拖拽动画。

### 场景：整理后内容不再需要纵向滚动

- **GIVEN** 整理前卡片跨越多个空行并产生纵向滚动。
- **WHEN** 用户点击“自动整理”。
- **THEN** 卡片一次性落到最终位置。
- **AND** 网格单元宽度不会因滚动条出现或消失而反复变化。

## 卡片全屏查看

系统 MUST 在每张状态正常的卡片右上角显示可访问的放大按钮。点击后 MUST 打开覆盖当前工作区的应用内模态弹窗，并在弹窗主体中挂载该卡片的独立沙箱实例。

全屏实例 MUST：

- 使用当前连接、主题、卡片文档、数据 API 和事件订阅能力；
- 以 `fullscreen` 作为尺寸标签，并按弹窗主体的实际像素尺寸发送环境和 resize 信息；
- 不提供移动与网格缩放手柄；
- 不修改 `board.json` 中的 `x/y/w/h`；
- 在弹窗关闭时销毁 iframe、Bridge、订阅和计时器；
- 不覆盖看板原卡片在宿主中的刷新与上下文菜单注册。

### 场景：打开并关闭全屏卡片

- **GIVEN** 看板上存在一张状态正常的卡片。
- **WHEN** 用户点击右上角放大按钮。
- **THEN** 弹窗显示卡片标题和铺满可用主体的卡片内容。
- **WHEN** 用户关闭弹窗。
- **THEN** 原卡片仍位于原布局位置，且可继续交互。
