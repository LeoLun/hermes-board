# 默认卡片增量规格

## 天气 12×4 横幅

天气卡片 MUST 在原 `card.json` 的 `sizes` 中声明 `12x4`，并继续使用 `8x8` 作为默认尺寸。天气原 `index.html` MUST 在 `12x4` 下同时容纳地点与当前天气、体感/湿度/风速、未来三天以及更换/刷新操作，不得产生横向滚动、内容裁切或宿主操作遮挡。

### 场景：天气切换到 12×4

- **GIVEN** 天气已有当前天气与未来三天数据。
- **WHEN** 用户把天气卡片调整为 `12x4`。
- **THEN** 当前天气、三项指标、未来三天和必要操作均在横幅内可见。
- **AND** 右上角宿主操作出现时不遮挡更换或刷新按钮。

### 场景：在 12×4 编辑城市

- **GIVEN** 天气以 `12x4` 显示。
- **WHEN** 用户进入更换城市状态。
- **THEN** 输入框、确定、取消和错误信息均完整可见并可操作。

## 所有默认卡片共用原 HTML 的全屏布局

时钟、天气、日历、番茄钟、待办、便签、世界时钟和倒数日 MUST 各自只使用 `card.json` 声明的唯一 `index.html` 同时支持网格与全屏。每张卡片 MUST 对 `fullscreen` 环境提供响应式布局，并根据实际 pixel 尺寸控制内容最大宽度、字号、列数和滚动区域。

所有默认卡片在全屏时 MUST：

- 保留网格模式中的数据读取、状态写入和用户操作；
- 在常见宽屏、窄屏和低高度窗口中不产生页面级横向滚动；
- 对超出可用高度的列表或编辑内容提供内部滚动，而不是裁掉操作；
- 避免核心内容无限拉伸或留下大面积无意义空白；
- 不复制或加载另一份全屏专用 HTML。

### 场景：默认卡片由网格进入全屏

- **GIVEN** 任意一张默认卡片正在网格中显示并已有可见数据。
- **WHEN** 用户打开该卡片全屏。
- **THEN** 全屏实例加载与网格实例相同的 `index.html`。
- **AND** 内容按全屏宽高重新组织，数据和交互能力保持一致。

### 场景：列表型卡片内容超过全屏高度

- **GIVEN** 待办、便签、世界时钟或日历的内容超过当前全屏主体可用高度。
- **WHEN** 卡片处于 `fullscreen` 环境。
- **THEN** 内容区可在卡片内部滚动。
- **AND** 主要输入或操作控件仍可到达，不被裁切在视口外。
