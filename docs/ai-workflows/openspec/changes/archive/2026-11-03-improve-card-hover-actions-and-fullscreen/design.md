# 设计：悬浮操作安全区与单 HTML 响应式全屏

## 1. 方案比较

### 方案 A：宿主悬浮操作组 + 默认卡片安全区（推荐）

宿主继续在 `CardFrame` 上层渲染按钮，将两个按钮放进统一操作组；默认卡片通过共享令牌和少量尺寸规则为右上角预留安全区。全屏仍复用当前沙箱和原始卡片文档，以 `data-size="fullscreen"` 驱动响应式布局。

优点是延续现有安全边界和全屏生命周期，改动集中、行为一致；代价是默认卡片需要逐张验证紧凑尺寸和全屏布局。

### 方案 B：把操作组移到卡片外部

操作组可完全避免覆盖 iframe，但紧密排列的卡片没有稳定外部空间，容易被滚动容器裁切或覆盖相邻卡片，命中区域和层级也更复杂。

### 方案 C：把宿主操作注入每张卡片 HTML

卡片可自行排版按钮，但会把宿主级布局删除和全屏生命周期暴露给不受信任沙箱，并迫使第三方卡片实现宿主交互，不符合现有 Bridge 权限边界。

采用方案 A。

## 2. 宿主操作组

`CardFrame` 用一个语义明确的操作容器包住两个原生 `button`：

1. 全屏按钮，使用 `screen-full` 图标；
2. 删除按钮，使用垃圾桶图标，调用现有 `services.removeCard(cardId)`。

操作组固定在卡片右上角。默认态使用 `opacity: 0`、`visibility: hidden` 和 `pointer-events: none`；以下任一条件成立时显示并恢复命中：

- `.hb-card:hover`；
- `.hb-card:focus-within`；
- 操作组自身持有焦点；
- 卡片处于键盘移动/缩放激活状态时仍保证已聚焦操作不会突然消失。

按钮继续阻止 pointer down/click 冒泡，避免误触卡片拖动。两个按钮都提供 `title`、包含卡片标题的 `aria-label` 和 `:focus-visible` 样式。淡入淡出遵循 `prefers-reduced-motion`。

删除按钮只调用布局 DELETE 接口，沿用 store 的 revision 冲突处理、toast 和 cron 暂停行为。这里不接入卡片包删除 API，也不清除远程数据，因此不额外弹出不可逆确认框。

## 3. 遮挡与安全区

操作组尺寸由宿主 CSS 统一定义，两个 30px 按钮加间距和边距形成稳定矩形。共享卡片令牌新增对应的右上角安全区变量，默认卡片在非全屏尺寸下让 `.hb-header` 或其操作区避开该矩形。

安全区只解决默认卡片内容与宿主操作的空间冲突，不把宿主按钮放进 iframe。紧凑尺寸如果无法在同一行容纳标题、卡片自身操作和安全区，则由该卡片的尺寸规则将自身操作换行、收缩或隐藏次要操作；不得把可见按钮留在宿主操作组下方。

全屏展示没有宿主悬浮操作组，`html[data-size="fullscreen"]` 不保留网格安全区。

## 4. 天气 12×4

天气 `card.json` 在 `sizes` 中加入 `12x4`，保持 `8x8` 为 `defaultSize`，默认布局不迁移。天气原 `index.html` 增加 `12x4` 规则：

- 左侧呈现地点、当前温度、天气状况与高低温；
- 中部呈现体感、湿度、风速；
- 右侧呈现未来三天；
- 更换和刷新操作避开宿主安全区；
- 编辑城市状态同样在横幅高度内完整可操作。

清单与默认布局测试继续确保所有实际布局尺寸均属于对应卡片声明。

## 5. 八张默认卡片的单 HTML 全屏适配

全屏继续通过 `FullscreenCardDialog → CardFrame(presentation)` 加载服务端返回的同一个 `entry` 文档，不增加 `fullscreenEntry`、复制文件或字符串分支。运行时已经把逻辑尺寸写入根元素；实现以 `html[data-size="fullscreen"]` 作为稳定选择器，并结合实际 pixel resize 进行自适应。

共享全屏基线包括更宽松但有上限的内边距、可滚动内容区以及适合大画布的字号/间距变量。各卡片按内容类型调整：

- 时钟、倒数日：核心数字保持视觉中心，并限制最大字号，避免超宽窗口无限放大；
- 天气、世界时钟、日历：使用多列或受控最大宽度，让信息密度随可用空间提高；
- 番茄钟：计时环和控制区在宽屏并排、窄屏上下排列；
- 便签、待办：编辑/列表区域铺满可用高度并独立滚动，输入与操作保持可达。

全屏 iframe 收到 `ResizeObserver` 产生的新 pixel 信息后，原文档必须原地重新布局，不重新加载、不切换 HTML，也不丢失编辑焦点或本地交互状态。

## 6. 验证策略

- 桌面结构测试验证操作组包含两个按钮、顺序正确、删除连接既有移除服务。
- CSS/可访问性测试验证默认隐藏、hover 与 focus-within 显示、pointer-events 和 reduced-motion 行为。
- 清单测试验证天气包含 `12x4` 且默认尺寸不变。
- 默认卡片文档测试验证八张卡片均只有一个 entry，并具备 `fullscreen` 响应规则；禁止引入第二份全屏 HTML。
- 用代表性的紧凑、默认、`12x4` 和多组全屏像素尺寸做渲染检查，重点检查按钮遮挡、横向/纵向溢出、滚动区域和焦点可达性。
